智能纪要

音频聚焦于 agentic 时代开源基金会和社区的发展，分享了华为对开源体系的思考，分析了开源发展阶段、面临的挑战、未来社区模式及基金会格局变化等内容，具体如下：

  • 开源发展阶段
      • 自由软件阶段
          • 时间界定：大致在 98 年之前。
          • 主导力量：以极客和个人为主导。
      • 开源基金会与大企业主导阶段
          • 时间范围：2000 年至 2020 年左右。
          • 代表基金会：诞生了 Eclipse、阿帕奇基金会等。
      • 国家和政府参与阶段
          • 时间区间：2022 年到 2025 年。
          • 典型案例：中国的开放原子开源基金会服务国家战略，美国和中国政府层面逐步加入开源生态。
      • 新型 AI 企业加入阶段
          • 时间展望：2025 年之后。
          • 发展趋势：OpenAI 等新型 AI 企业加入，未来可能诞生新的基金会或托管平台，托管要素包括数据和 skill 等。
  • 华为开源参与历程
      • 参与使用阶段
          • 时间跨度：2008 年或 10 年左右至 2012 年左右。
          • 参与内容：主要参与和使用开源，以 Linux 为主。
      • 参与基金会阶段
          • 时间范围：2012 年到 2019 年美国制裁前。
          • 参与对象：参与 Linux 基金会、Eclipse 等开源基金会。
      • 项目主导发起阶段
          • 时间节点：2019 年美国制裁后。
          • 发起原因：与业务连续性相关，发起多个开源项目。
      • 生态和创新视角阶段
          • 时间区间：去年以来 AI 时代来临后。
          • 代表社区：华为有自己的 Open 9 问社区。
  • 开源基金会现状分析
      • Linux 基金会
          • 参与深度：华为是国内参与 Linux 基金会最深的企业，参与了至少 11 - 12 个子基金会。
          • 开源 AI 框架：依托 PyTorch 和云原生的 CNCF，辐射 AI 全栈系统，但不托管 AI 大模型。
      • AARF：更多聚焦以 MCP 协议为主，不涉及 anthropic 应用和模型层。
      • AIF
          • 加入情况：华为今年二月初加入，成为首批黄金会员，国内还有联想参与。
          • 发展速度：会员数量以每月四五十家的速度快速增长。
  • 基金会托管面临的挑战
      • 成本和商业模式
          • 开发成本：开源 AI 大模型开发成本比传统软件高出几个数量级。
          • 会费压力：中小公司无力缴纳高额会费，难以承担基础设施要求。
          • 投资压力：项目托管给基金会，数亿美元的基础设施投资会带来很大压力。
      • 基础设施：开源 AI 领域需要大量算力，现有基础设施难以胜任大模型协作开发。
      • 开发者激励与参与度
          • 代码生成：agent 到来后，从 AI 生成代码的 token 消耗可能比从 GitHub 下载更省。
          • 动力改变：开发者参与开源社区的核心动力可能发生改变。
      • 地缘政治因素：华为等企业的开源项目受地缘政治影响，需考虑相关问题。
  • 开源项目发展情况
      • 项目井喷：OpenClaw 开源后，围绕 agent 的项目在 GitHub 和 Hugging Face 上呈现井喷式发展。
      • 未来社区模式
          • 模式转变：开源社区将从协作集市转变为 agent 代理驱动的协作和分发社区。
          • 功能侧重：分发功能可能至少持平或大于协作功能。
  • 开源运营思考
      • 指标调整：传统的 star 数、开发者数量等指标可能不再适用于智能体时代的开源项目，需调整为社区对 agent 友好度、token 效率值、项目被 agent 引用次数等指标。
      • 人机共生状态：短期之内人机共生，agent 和 agent 之间无人参与的过程不会很快到来，两者将双轨并行。
  • 开源基金会格局变化思考
      • 明星项目重要性：Linux 基金会依托 Linux Kernel，CNCF、Eclipse 等也有其明星项目，开源项目对基金会至关重要。
      • 主导力量转化：主导开源项目和开发者的力量正在发生重大转化。
      • 全球型基金会需求
          • 法律限制：现有基金会多受美国法律管控，需要不受单一国家法律限制的全球型基金会。
          • 募资对象：募资对象可能包含国家力量和 Token 提供商。
      • AI 模型生态系统：业界缺少端到端的 AI 模型生态系统，尤其是以开源 AI 模型为主的组织或机构。
      • agentic OS 思考：对于 agentic OS 是围绕大模型还是更偏上层，目前尚无结论。

本章节中，来自华为开源的说话人1汇报对agentic时代开源基金会和社区的思考。谈论开源时，开源组织如Linux、Apache等基金会是项目和社区治理的重要组织基础，开源项目是开源体系核心，开发者围绕其依托开源license协作。而在agent引入的时代，基金会和开源项目将面临变化与挑战。
01:35华为总结开源体系各阶段发展及未来趋势
本章节是华为对开源体系的总结。98年之前是开源0.1阶段，以极客和个人主导；2000 - 2020年由开源基金会和大企业主导，诞生了Eclipse、阿帕奇等基金会；2022 - 2025年国家和政府参与开源，如中国开放原子开源基金会；25年后新型AI企业加入，未来或有新基金会、托管平台，托管要素也将增多。
03:31项目变化下开源从人与人协同走向人与Agent协同
本章节说话人1分享了关于项目变化的思考，指出由于agent的引入，会出现新的治理和协作模式。在开源社区中，不再仅是人参与开源和协作，还有新型agent等协同。整体上，开源正从人与人的协同走向人与agent的协同。
04:04华为不同阶段开源参与情况及视角转变
本章节主要介绍了华为参与开源的历程。2008 - 2012 年主要参与和使用开源，以 Linux 为主；2012 - 2018 年参与开源基金会，如 Linux 基金会、Eclipse 等；2019 年受美国打压制裁，发起多个开源项目以保障业务连续性；近两年 AI 时代来临，华为有 Open 9 问社区，更多从生态和创新视角出发。
05:23华为在Linux基金会及其子基金会投入大
本章节说话人1以Linux基金会为主进行分享，指出在国内华为是参与Linux基金会最深的企业。华为不仅参与Linux基金会本身，还参与了其至少11到12个子基金会，并且在国内对Linux基金会相关事务的投入是最大的。
05:55Linux等基金会AI开源协作及AIF发展情况
本章节介绍了开源AI相关情况。Linux基金会依托PyTorch和CNCF辐射AI全栈系统，不托管AI大模型；AARF聚焦MCP协议，不涉及特定应用和模型层。Linux基金会持续引领AI开源协作。华为2月初加入AIF成为首批黄金会员，其会员数量快速增长，截止6月15日达200多家，且速率为每月四五十家 。
08:47基金会托管大模型及Agent面临成本等挑战
本章节说话人1回到之前问题，提及基金会模式在托管大模型及与agent相关时面临挑战并列出五点，首先是成本和商业模式方面。开源AI大模型开发成本比传统软件高出多倍，众多AI供应商尤其是中小公司无力缴纳高昂会费，且即便缴纳会费也很难达成某种效果。
09:30开源项目托管及AI协作开发的基础设施难题
本章节主要提出两个问题，一是将项目托管给开源基金会时，基础设施投资动辄数亿美元，会给基金会带来较大压力；二是当前开源软件在 GitHub 社区协同，而开源 AI 领域需要大量算力，但现有的基础设施可能还无法胜任 AI 大模型协作开发平台的要求。
10:06开发者参与开源社区动力或变及华为受影响问题
本章节主要围绕开发者激励和参与度展开思考。在智能体时代，随着 agent 到来，未来 AI 从 0 生成代码的 token 消耗可能比从 GitHub 搜索下载更省，若此逻辑成立，开发者参与开源社区的核心动力可能改变。此外，还提到华为受地缘政治等诸多因素影响，在开展开源项目时需考虑相关问题。
11:06OpenClaw开源后Agent项目呈井喷式发展
本章节主要提及了基金会情况与开源项目。指出OpenClaw开源后围绕agent的项目呈现井喷式发展，展示了一个月前在GitHub和hugging face上的数据，还提到字节的Dearflow，虽当前其中数据不多，但强调agent项目未来绝对会呈现井喷式发展态势。
11:45华为思考下一个时代开源模式及社区走向
本章节说话人1表示正在思考华为下一个时代开源模式，这是内部初步思考。提及通过AI获取GitHub数据，其每月AI辅助和主导的PR超2000万，Hugging Face是分发高地。结合推理成本下降的情况，认为未来开源社区将从协作集市转变为agent代理驱动的协作和分发社区，分发功能作用可能至少持平或大于协作。
13:19华为开源运营思考及未来度量指标探讨
本章节主要围绕开源社区的开源运营展开思考。华为开源系统部在面向开发者运营时，考虑引入 agent 后是否有 agent real。当前传统指标如 star 数、开发者数量可能不再匹配项目成功度，未来或用社区对 agent 友好度等指标衡量。短期内人机共生中 agent 间无人参与的情况不会很快到来，过程将是叠加和双轨并行，这只是初步思考。
15:47Agentic时代开源基金会格局变化及力量转化
本章节说话人1表示正在思考 agentic 时代对开源基金会格局的影响。回顾过去，90年代 Linux 基金会依托 Linux Kernel，2010年左右 CNCF、Eclipse 有 IDE，2020 年开放原子有 OpenHarmony、Open 欧拉等，凸显开源项目对开源基金会的重要性，同时指出主导开源项目和开发者的力量正发生重大转化。
16:39建立全球型开源基金会的初步想法与考量
本章节说话人提出初步想法，认为需要一个真正全球型的基金会，注册地和管辖法律不能受单一国家（主要是美国）法律限制。提到联合国等关注开源并尝试成立相关组织，新基金会募资对象和成员未来可能含国家力量等基础设施要素。还指出开源基金会中Token 提供商稀缺，若不能解决Token供应，可能无法托管大模型等项目。
18:00业界缺少端到端开源AI模型生态系统及组织
本章节主要是团队的初步思考。业界缺少端到端的AI模型生态系统，尤其缺乏以开源AI模型为主的组织或机构，围绕其可发展与AI相关的训练推理等软件。虽Linux基金会有训练和推理项目，但仍有很多训推软件不在其旗下。
18:43Agentic OS思考存疑，探索开源AI模型新系统
本章节说话人1提出对未来agentic OS是围绕大模型还是更偏上层存在疑问，暂无结论。提到这是内部专家想法，类比开源AI模型对应计算时代的Linux Kernel，希望基于异构硬件构建统一开源AI模型，围绕其构建新组织和系统，目前处于初步尝试和探索阶段。
